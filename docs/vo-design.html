How vo works

The design of the voice-over controls in voiceover. Written 2026-11-16, from the voice-engine branch (branched from main at 6d83764).

The short version. vo and voice are two names for one 127-line bash script. It is the control panel for a tool that reads Claude Code's replies aloud with Kokoro, a free text-to-speech model that runs on your Mac. The script is a shell command, not a Claude Code feature, because everything it controls is an operating-system process (the audio player and the speech generator) and a few flag files. It does not speak anything itself.

1What vo is, and what it is not

The script lives at _tools/speak-claude/voice. The installer links it into ~/.local/bin twice, as voice and as vo, so both names run the same code. Inside Claude Code you run it with a ! in front (! vo pause). That runs it in your shell and sends nothing to the model.

The script plays two roles:

  • Commands you type: stop, pause, resume, again, status, mute, unmute, read, help.
  • A hook entry point: voice --on-prompt is registered as Claude Code's UserPromptSubmit hook, so speech stops when you send your next message.

It is not the part that decides what to say or makes the audio. That is a separate hook (speak_reply.py) and the engine behind it.

3How the pieces connect

4Life of one reply

  1. Claude Code runs the Stop hook. It passes JSON on stdin that includes session_id and last_assistant_message. If an older Claude Code sends no reply text, speak_reply.py reads the last 4 MB of the transcript instead. It never reads the whole transcript, which can pass 100 MB.
  2. It checks, in this order, whether to stay silent: the global flag ~/.claude/.speak-off; the environment variable SPEAK=0; the file ~/.claude/speak-muted/<session_id>; a reply under 120 characters; a reply with nothing worth saying aloud. Each skip is written to speak.log with the reason.
  3. It cleans the text for the ear. Code blocks, tables, headings and block quotes are dropped. Lists are kept, markdown marks are removed, dashes become commas, long file paths become the name on the end ("the file template, line 12"), scripts the English voice would spell letter by letter are removed, and "m²" becomes "m squared". Anything over 5000 characters is cut at a sentence end.
  4. It starts the speech and leaves. It kills any older speech, saves the text as this session's last reply, starts speak.py detached, and exits 0 straight away so the turn is never held up.
  5. speak.py gets the engine ready. It saves last.txt, deletes the old last.wav, and starts voice_server.py if no engine is listening (waiting up to 30 seconds). If the engine cannot be used at all, it loads Kokoro itself.
  6. It cuts the text into growing chunks. The first chunk is at most 80 characters so sound starts quickly. Each next chunk can be up to 1.8 times longer, with a ceiling of 250. Chunks end at sentence ends, or at commas for a very long sentence.
  7. Each chunk is made while the last one plays. The engine returns a WAV path over the socket, and speak.py adds the audio to its player's queue when the chunk playing has 0.3 seconds left, so the chunks play with no gap. Generation runs about 2.2 times faster than speech, so the next chunk is ready in time.
  8. The whole reply is saved for vo again. After the last chunk, the audio is joined into last.wav through a temporary file and a rename, so a half-written file is never played.
  9. Your next message ends it. The UserPromptSubmit hook runs voice --on-prompt, which stops the speech. The exception is a message that is itself a voice command, such as ! vo resume, which must not kill the speech it is aiming at.

5The commands

The script lowercases the first word and strips leading dashes, so stop, -stop and s all work, and vo -mute here is the same as vo mute here.

8Design rules, and why each exists

  • A hook must never block or fail a turn. Speech runs in a detached process, and speak_reply.py exits 0 on every path, exceptions included. A broken voice must not break your work.
  • --on-prompt prints nothing. What a UserPromptSubmit hook prints is added to Claude's context.
  • Pause is a signal speak.py handles, not SIGSTOP. It used to freeze afplay with SIGSTOP, but the Mac's sound clock kept running, so resume skipped ahead. speak.py sets its handlers before its slow imports, because an unhandled SIGUSR1 kills a process.
  • The engine's file name must not contain speak.py. vo stop kills anything matching that, and the engine should survive a stop.
  • Speech must work without the engine. Every engine failure falls back to loading Kokoro inside speak.py, which is slower but audible.
  • Voice commands must not stop the speech they target. The on-prompt hook exempts messages that start with voice or vo.
  • A reply is spoken once, even with old and new hooks installed. The Stop hook skips a reply another copy of it took in the last minute, and the SessionStart hook tells you to run ./uninstall.sh.
  • last.wav is written only when complete. An interrupted reply leaves no partial recording behind.
  • Nothing that changes is written into the plugin's folder. It is replaced with every update; everything goes in ~/.claude/voiceover.
  • Use uv, never pip, and keep onnxruntime at 1.23.2. It is the last version with Intel Mac builds.

9When something fails

FailureWhat happens
Hook input is unreadableLogged as skipped, exit 0.
Engine not runningspeak.py starts it and waits up to 30 seconds; the first reply is slower (about 6 seconds to first sound instead of about 3).
Engine unreachable or dies mid-replyspeak.py loads Kokoro itself and finishes the reply.
Speech stopped half-wayNo last.wav exists, so vo again regenerates from last.txt.

Engine idle for 45 minutesIt quits and frees about 500 MB. The next reply starts it again.

10Worth knowing

Not on main yet. The voice engine (voice_server.py) and the edits that use it live on the voice-engine branch. Until that branch is merged, main still has the version without the engine.

  • One voice at a time. By design, a new reply replaces whatever is still being read. With several sessions open, the last reply to finish wins, and stop, pause and resume reach all of them. To keep a session quiet, mute it with mute here or start it with SPEAK=0.
  • Global mute overrides everything. While ~/.claude/.speak-off exists, mute here changes nothing you can hear. Use vo unmute to hand control back to the per-session files.
  • Short replies are skipped. Anything under 120 characters is not spoken, which keeps notices like "Login expired" silent but also silences genuinely short answers.
  • Mac only. The install script and the voice script assume macOS (playback itself, through sounddevice, would work elsewhere). The idle engine holds about 500 MB of memory for up to 45 minutes.
  • The older docs predate the engine. guide.html (last changed 2026-10-15) and rebuild-prompt.md (2026-11-06) do not mention voice_server.py, the flag-file locations, or vo read.
