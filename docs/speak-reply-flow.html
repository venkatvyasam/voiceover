speak_reply.py in plain terms

What the hook does after every Claude reply, and the order it does it in. Part of voiceover. Written 2026-11-16.

In one sentence: speak_reply.py is the gatekeeper and editor of the voice-over. After each reply it decides whether the reply should be read aloud, cuts out the parts that sound bad when spoken, hands the rest to speak.py, and leaves. It makes no sound itself.

1Where it fits

Claude Codefinishes a reply
→
speak_reply.pydecides what, if anything, to say
→
speak.pyturns the text into sound
→
Your speakersplay it

It is a Stop hook: a command that Claude Code runs by itself each time a reply is finished. Claude Code hands it a small JSON message that includes the reply text and the session ID.

2The flow

3The checks, in plain words

  1. Muted for everyone? vo mute creates one flag file. If it exists, nothing is spoken in any session.
  2. A quiet session? Two ways to get here: you started that session with SPEAK=0 claude, or you ran vo mute here, which leaves a file named after that session's ID.
  3. Too short, or no reply? Claude Code sends the reply text itself. Anything under 120 characters is skipped, because short messages are usually notices such as "Login expired". If an older Claude Code sends no text at all, the hook reads the end of the transcript file (the last 4 MB only) and takes the last long reply from there.
  4. Nothing left to say? After cleaning, a reply made only of code, tables or headings has no words left. It stays quiet instead of reading out nothing.

The order matters. The cheap checks come first, so a muted session costs almost nothing.

4The cleaning step, with a real example

Text that looks fine on a screen often sounds bad aloud. Nobody wants to hear a table read cell by cell. So the hook edits the reply before it goes on. The example below was run through the real cleaning function, speakable().

The cleaning also removes writing the English voice would spell out letter by letter (Arabic or Chinese, for example), and says "m²" as "m squared". Anything over 5000 characters is cut at a sentence end.

5What it writes down

Every decision, spoken or skipped, becomes one line in speak.log. vo status shows the latest one, which is the fastest way to find out why a reply was silent.

6Three rules it keeps

  • Never hold up Claude. The speech runs in its own detached process, and the hook exits at once.
  • Never break a turn. Every path ends in exit 0, even after an error. A broken voice must not break your work.
  • Never read the whole transcript. Transcripts can pass 100 MB, so the fallback reads only the last 4 MB.

7Worth knowing

  • Short answers are silent. The 120-character floor keeps notices quiet, and also silences a genuinely short reply.
  • The newest reply wins. Before starting, the hook stops any speech still running, from any session.
  • It only decides. Voice, speed and chunking live in speak.py. Stopping, pausing and muting live in the vo script.

8Try it without speaking

From the voiceover folder, this prints what would be spoken and makes no sound and no log line:

echo '{"session_id":"test","last_assistant_message":"<a reply of 120 or more characters>"}' \
  | ~/.claude/voiceover/.venv/bin/python speak_reply.py --dry-run

The dry run still obeys the mute switches. If it prints nothing, run vo status first: a global mute produces silence here too.
